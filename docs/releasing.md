# Releasing

A release is a tag. Push `v1.2.0` and the [Release workflow](../.github/workflows/release.yml) tests that commit, builds a universal Codec.app (Apple silicon and Intel), puts it in a disk image, publishes `Codec-1.2.0.dmg` to GitHub Releases, and points the Homebrew cask at it. Installed copies of Codec see the new version at their next daily check.

The repository has to be public, as it is: Codec's update check asks GitHub's API without signing in, and Homebrew downloads the disk image the same way.

## Signing

Releases aren't notarized by Apple, as that takes an Apple Developer Program membership. So macOS stops Codec the first time people open it, and they allow it with Open Anyway in System Settings › Privacy & Security. The release notes say how, the cask prints it, and Codec's update alert says it too when it offers a download. A version Codec installs itself isn't stopped: macOS only checks files that come from a browser or another app that marks them as downloaded.

They are **signed with a self-signed certificate**, so that every version has the same identity. macOS remembers the permissions people give an app (Full Disk Access, the camera, controlling other apps) by that identity: with it, they survive updates; signed ad hoc, as builds from source are, every update would ask for them again. The certificate costs nothing, and Gatekeeper doesn't trust it, which is fine: it's only there to stay the same.

It's also what Codec checks before installing an update itself: the new app has to satisfy the running one's designated requirement, which names this certificate. **Keep a copy of it.** Released with a new certificate, a version still installs by download, but copies signed with the old one won't install it themselves.

The workflow signs with whatever certificate is in two secrets, in the repository's Settings › Secrets and variables › Actions:

| Secret | What it is |
|---|---|
| `SIGNING_CERTIFICATE` | The certificate and its private key, as a base64-encoded `.p12` |
| `SIGNING_CERTIFICATE_PASSWORD` | The `.p12`'s password |

Without them, releases are signed ad hoc.

### The self-signed certificate

```bash
scripts/make-signing-certificate.sh
scripts/make-signing-certificate.sh --github
```

The first makes "Codec Release Signing" in `~/.codec-signing`, readable only by you; the second stores it in the two secrets with `gh`. **Back that folder up** (a password manager will take both files): a new certificate is a new identity, and everyone would grant Codec its permissions once more. The script won't overwrite it.

### With a Developer ID, later

With an [Apple Developer Program](https://developer.apple.com/programs/) membership (99 USD a year), put your Developer ID Application certificate in `SIGNING_CERTIFICATE` instead and add three more secrets. The workflow then signs with the hardened runtime, has Apple notarize the app and the disk image, and macOS opens it like any app from the web. Delete the cask's `caveats` then; the release notes stop including the Open Anyway steps on their own. Changing certificates changes Codec's identity, so permissions are asked for once more, that one time.

| Secret | What it is |
|---|---|
| `SIGNING_CERTIFICATE` | Your Developer ID Application certificate and its private key, exported from Keychain Access as a `.p12`, then base64-encoded: `base64 -i Codec.p12 \| pbcopy` |
| `SIGNING_CERTIFICATE_PASSWORD` | The password you gave the `.p12` when exporting it |
| `NOTARY_KEY` | An App Store Connect API key's `.p8` file, as text: `pbcopy < AuthKey_XXXXXXXXXX.p8` |
| `NOTARY_KEY_ID` | That key's ID (the `XXXXXXXXXX`) |
| `NOTARY_ISSUER_ID` | The issuer ID shown above the keys list |

To get them:

1. **Certificate**: in Xcode › Settings › Accounts › Manage Certificates, add a *Developer ID Application* certificate (or create one at developer.apple.com › Certificates). In Keychain Access, under My Certificates, right-click it › Export, as `.p12`.
2. **API key**: at [App Store Connect › Users and Access › Integrations › App Store Connect API](https://appstoreconnect.apple.com/access/integrations/api), generate a team key with the *Developer* role and download its `.p8` (you can only download it once).

## Cutting a release

1. Make sure `main` is green in CI.
2. Tag the commit and push the tag. An annotated tag's message becomes the release notes, which Codec shows in its update alert, so say what's new in it; Markdown works. A lightweight tag gets notes generated by GitHub instead.

   ```bash
   git tag -a v1.2.0 -m "Faster splits, and the history search remembers its filter"
   git push origin v1.2.0
   ```

   For longer notes, write them in a file. Git drops lines starting with `#` from a tag message, Markdown headings included, unless you pass `--cleanup=verbatim`:

   ```bash
   git tag -a v1.2.0 --cleanup=verbatim -F notes.md
   ```

3. Watch the Release workflow (about 15 minutes, most of it testing; notarizing adds a few more). It ends by committing the cask's new version and checksum to `main`.

A version with a hyphen, like `v1.3.0-beta.1`, is published as a prerelease: the cask stays on the last release, and the update check doesn't offer it, since GitHub's latest release never is one.

To write the notes in GitHub's editor instead, create a draft release for the tag first; the workflow adds the disk image to it and leaves the notes alone (publish it once the image is there).

## Versions

The version comes from the tag: the workflow passes it to `scripts/build-app.sh`, which stamps `CFBundleShortVersionString`, and the build number (`CFBundleVersion`) counts commits. `Resources/Info.plist` keeps a placeholder. Builds from source take the latest `v*` tag, so a checkout of `main` doesn't keep offering the release it already has.

## Building a release on your Mac

`scripts/release.sh` is what the workflow runs. `make release VERSION=1.2.0` builds the disk image signed ad hoc; `CODEC_SIGN_IDENTITY="Codec Release Signing"` signs it with the self-signed certificate, once it's imported into your keychain (open `~/.codec-signing/codec-signing.p12`). With a Developer ID certificate in your keychain, it signs and notarizes instead:

```bash
xcrun notarytool store-credentials codec --key AuthKey_XXXXXXXXXX.p8 --key-id XXXXXXXXXX --issuer <issuer ID>
CODEC_SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" CODEC_NOTARY_PROFILE=codec make release VERSION=1.2.0
```

It writes `build/Codec-1.2.0.dmg` and prints its SHA-256. `scripts/update-cask.sh 1.2.0 build/Codec-1.2.0.dmg` then updates the cask, if you publish it by hand.

## Trying an update before releasing

`CODEC_RELEASES_URL` points Codec's update check at a release's JSON, in the shape of GitHub's API, instead of GitHub. To see a copy install the next one: sign two builds with the same certificate, at two versions, put the newer one in a disk image, and serve the JSON and the image from your Mac.

```bash
shasum -a 256 Codec-1.2.1.dmg   # the asset's digest, as "sha256:<hex>"
cat > latest.json <<'EOF'
{"tag_name": "v1.2.1", "html_url": "http://127.0.0.1:8765/", "body": "What's new",
 "assets": [{"name": "Codec-1.2.1.dmg", "browser_download_url": "http://127.0.0.1:8765/Codec-1.2.1.dmg",
             "digest": "sha256:<hex>"}]}
EOF
python3 -m http.server 8765 --bind 127.0.0.1 &
open --env CODEC_RELEASES_URL=http://127.0.0.1:8765/latest.json /path/to/Codec-1.2.0/Codec.app
```

Give the test builds another `CFBundleIdentifier` (`com.srozen.codec.updatetest`), so they keep their own settings and saved windows rather than sharing yours.

## Homebrew

The cask is [`Casks/codec.rb`](../Casks/codec.rb), in this repository, which works as its own tap:

```bash
brew tap srozen/codec https://github.com/srozen/codec
brew install --cask srozen/codec/codec
```

`brew upgrade --cask srozen/codec/codec` picks up a new release once the workflow has updated the cask. Codec knows when Homebrew installed it, and its update alert puts that command at the prompt instead of offering the download.

## Hardened runtime

Builds signed with a Developer ID run under the hardened runtime, with the exceptions in [`Resources/Codec.entitlements`](../Resources/Codec.entitlements): sending Apple Events, and the camera and microphone. macOS holds Codec responsible for the programs its panes run, so without them a script calling `osascript`, or a tool recording audio, couldn't even ask for permission. Each still asks you first, with the usage descriptions in `Info.plist`.
